# Контракт backend

JSON UTF-8. Все методы кроме `/health`, `/auth/device`, `/auth/refresh` требуют `Authorization: Bearer <access_token>`. Ошибки: `{ "message": "…" }` с подходящим HTTP status. Внешний сервер должен использовать HTTPS.

| Метод | Путь | Данные / результат |
|---|---|---|
| GET | `/health` | Доступность backend |
| POST | `/auth/device` | `{device_id}` → `{access_token, refresh_token, expires_in, remaining, subscribed}` |
| POST | `/auth/refresh` | `{refresh_token}` → новая пара токенов и аккаунт; старый refresh аннулируется |
| GET | `/account` | `{remaining, subscribed}`; при необходимости сверяет сохранённый чек с Google |
| POST | `/generations` | `{request_id, messages:[{role,content}]}` → `{generation_id, remaining, subscribed}` |
| GET | `/generations/:id/events?after=N` | SSE только с событиями после N |
| POST | `/generations/:id/cancel` | `{}` → `{ok:true, remaining, subscribed}` |
| POST | `/generations/:id/retry` | `{request_id}` → новая генерация после ошибки AI; резервирует ранее возвращённое сообщение |
| POST | `/billing/verify` | `{purchase_token}` → серверная проверка Google Play и аккаунт |

`request_id` — UUID сообщения ассистента. Повтор POST с тем же ID возвращает ту же генерацию, пока она хранится на сервере. Доступ к чужим генерациям возвращает 404.

SSE:

```text
id: 1
event: delta
data: {"id":1,"type":"delta","text":"Привет"}

id: 2
event: done
data: {"id":2,"type":"done","remaining":2,"subscribed":false}

```

События: `delta`, `done`, `cancelled`, `failed`. Они имеют возрастающие ID. `failed` дополнительно содержит `message`. `auth_expired` — служебное событие текущего соединения без ID; после него сервер закрывает соединение, сама генерация продолжается. Клиент обновляет токен и передаёт последний **сохранённый в Room** ID при переподключении. Комментарии `: heartbeat` не являются данными.

HTTP 401 до открытия стрима и `auth_expired` после открытия обрабатываются отдельно. В уже открытом ответе невозможно заменить HTTP 200 на 401.

Клиентская потеря сети: ручное возобновление того же потока. Окончательная ошибка провайдера: новый ответ на прежний вопрос, прежний частичный ответ сохраняется отдельно. Это разные операции.

При принятии запроса сервер резервирует сообщение. `done` фиксирует расход; `failed` и `cancelled` возвращают резерв единожды. Терминальные события содержат `remaining` и `subscribed`. Пустой ответ считается ошибкой. Отключение только SSE-клиента не означает сбой генерации: сервер продолжает работу; после переподключения клиент узнаёт результат и актуальный лимит.

Cloudflare хранит события в SQLite Durable Objects; завершённый ответ доступен после перезапуска объекта. Потерянная при перезапуске незавершённая генерация помечается `failed`, её резерв возвращается. Завершённые генерации очищаются через час при последующей активности. Токены облачного и локального backend не взаимозаменяемы.
