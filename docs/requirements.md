# Требования из Figma и состояние выполнения

Источник: пять скриншотов задания, предоставленные пользователем 28 сентября 2026 года. Эти критерии сохраняются при любых изменениях дизайна.

Пользователь отдельно потребовал: **никаких деморежимов, фиктивных AI-ответов или поддельных покупок**. Реальный OpenRouter подключён через Cloudflare Secret; локальный `.env` исключён из Git. Изолированные фикстуры используются только в автоматических тестах.

## 1. Пустой чат

> При первом запуске приложение получает токен по device_id. Счётчик бесплатных сообщений (например, 3). Кнопка отправки неактивна, пока поле пустое.

**Что сделано:** случайный хеш ANDROID_ID, POST `/auth/device`, access/refresh токены, сохранение через Android Keystore. Сервер хранит остаток лимита; новый аккаунт получает 3 сообщения. Пустой и пробельный ввод заблокирован и в UI, и в ViewModel.

**Доказательства:** backend-тест сохранения аккаунта/лимита и тест идемпотентного списания проходят; живой UI-тест проверил неактивную пустую отправку и реальный первый запрос. Отсутствующий ключ не списывает сообщение.

**Статус:** реализовано, проверено. Device ID соответствует установке: переустановка создаёт новый UUID; это не антифрод.

Файлы: `network/Auth.kt`, `ui/ChatViewModel.kt`, `ui/ChatScreen.kt`, `server/server.mjs`.

## 2. Стриминг ответа

> Ответ приходит по SSE и выводится по мере поступления, с Markdown (заголовки, списки). «Стоп» прерывает генерацию, частичный ответ сохраняется. Если токен истёк посреди стрима — обновить и продолжить без потери текста; параллельные запросы не должны обновлять токен одновременно.

**Что сделано:** реальный SSE OpenRouter через backend; OkHttp + Flow; Markdown через Markwon. Каждое событие сохраняется в Room вместе с event ID. «Стоп» отменяет клиентский запрос и отправляет отмену backend. Refresh защищён Mutex; после обновления клиент подключается к той же генерации с последнего сохранённого события. Дубли event ID игнорируются.

**Доказательства:** получен настоящий ответ OpenRouter в Android-приложении. Backend-тест проверяет истечение токена во время потока и точное совпадение итогового текста после продолжения. Другой тест проверяет терминальность «Стоп». JVM-тест запускает 20 конкурентных refresh и подтверждает единственный запрос обновления. Room-тест подтверждает, что повторное событие не дублирует текст.

**Статус:** реализовано; реальный стрим и Markdown проверены на эмуляторе, сбои/refresh/остановка проверены автоматическими тестами. Ручная проверка всех вариантов на настоящем провайдере не заявляется. Прекращение вычислений у самого провайдера зависит от его поддержки отмены.

**Замечание пользователя:** первый ответ случайно выбранной бесплатной модели смешивал языки и содержал выдуманные названия. Это проблема качества AI, не парсинга SSE. Случайный роутер заменён на закреплённую бесплатную `nvidia/nemotron-3-super-120b-a12b:free`, добавлена системная инструкция на грамотный русский язык, краткость и проверку собственных имён. Повторный ответ на тот же вопрос получен и в прямой проверке API, и в приложении; смешения письменностей в проверенном тексте не было. Это не гарантирует отсутствие всех фактических и грамматических ошибок модели.

Файлы: `network/SseParser.kt`, `network/Api.kt`, `network/Auth.kt`, `data/ChatRepository.kt`, `data/ChatDatabase.kt`, `server/server.mjs`.

## 3. Ошибка сети

> Обрыв соединения или ошибка сервера: полученная часть ответа остаётся, показываем причину и «Повторить». Никаких бесконечных повторов и разлогина из-за обычной сетевой ошибки.

**Что сделано:** частичный ответ и курсор сохраняются в Room. UI показывает причину и кнопку ручного повтора. Для временных сетевых сбоев добавлены максимум два автоматических повтора с паузами 1 и 3 секунды. Исчерпанный лимит, неверный запрос и терминальный отказ AI не повторяются автоматически. Обычный HTTP повторяется максимум один раз после refresh; SSE допускает максимум три refresh на попытку. Сетевая ошибка не очищает сессию.

При клиентском обрыве автоматическое переподключение или ручной повтор продолжает ту же генерацию. Если сам AI-провайдер окончательно завершил поток ошибкой, прежний фрагмент остаётся отдельным сообщением, а повтор запускает новый ответ на исходный вопрос с резервированием ранее возвращённого сообщения. Ошибка или отмена возвращает резерв, успешный результат расходует одно сообщение. Для такого повтора есть серверный предел в три попытки.

**Доказательства:** backend-тест отключает SSE-клиента, переподключается с курсором и проверяет отсутствие потерь/дублей; тест ошибки провайдера подтверждает сохранённый фрагмент и отсутствие повторного списания. JVM-тесты подтверждают сохранение токенов при 503 и отсутствие бесконечного цикла при повторном 401.

**Статус:** реализовано, автоматические проверки пройдены. Облачный буфер событий хранится в SQLite до часа. Завершённые потоки переживают пересоздание объекта; потерянные незавершённые генерации помечаются ошибкой с возвратом резерва. Локальный текст остаётся в Room. В итоговом APK также проверен настоящий сбой бесплатного AI-провайдера: UI показал ошибку, однократный ручной повтор завершился реальным ответом, лимит не списался повторно (LiveRetryTest). Отключение реальной сети вручную остаётся в чек-листе.

## 4. Список чатов

> История хранится локально (Room): после перезапуска приложения всё на месте. Группировка по датам, поиск по названию. Название чата — из первого сообщения.

**Что сделано:** таблицы Room `chats` и `messages`, внешний ключ и индекс. Заголовок — первые 55 символов первого сообщения. Группы «Сегодня», «Вчера», «Ранее», поиск без учёта регистра, открытие истории и создание чата. Добавлено удаление с подтверждением и каскадным удалением сообщений. Незавершённое сообщение после нового запуска превращается в ошибку с возможностью продолжения.

**Доказательства:** Android-тест физически закрывает и повторно открывает файловую Room-базу, проверяет заголовок, текст, курсор и восстановление статуса. Живой UI-тест проверил историю, поиск «Стамбул» и сохранение ответа после пересоздания Activity.

**Статус:** реализовано, проверено на эмуляторе. Пересоздание Activity и повторное открытие базы не выдаются за ручной тест полного выключения устройства.

## 5. Пейвол

> Показывается, когда бесплатный лимит исчерпан. При старте проверяем активную подписку, есть «Восстановить покупки». Саму покупку можно замокать, цены приходят из стора / Adapty.

**Что сделано:** после последнего успешного бесплатного ответа автоматически открывается пейвол; при новом запросе сверх лимита он также открывается; сервер дополнительно блокирует запрос HTTP 402. При запуске запрашиваются аккаунт и покупки Google Play. Цены приходят из ProductDetails, есть выбор тарифа, launchBillingFlow, обработка pending/cancelled, restore, серверная проверка чека через Google Play Developer API и acknowledge после проверки. Фиктивных покупок нет по отдельному требованию пользователя.

**Доказательства:** backend-тест подтверждает блокировку четвёртого нового запроса. Живой UI-тест открыл пейвол. API не содержит эндпоинта фиктивной покупки.

**Статус: частично подтверждено, внешняя настройка не завершена.** Товары `chat_weekly` и `chat_monthly`, тестовый трек, аккаунт тестировщика и сервисный аккаунт Google Play не предоставлены. Поэтому реальные цены, успешная оплата, восстановление и серверная проверка настоящего чека ещё не проверены. По последующему прямому запросу пользователя при недоступности магазина отображаются цены из макета (499 ₽ / 1 290 ₽) с пометкой «ТЕСТОВЫЕ ЦЕНЫ». Продолжить оплату по ним нельзя; подписка не активируется фиктивно.

Приёмку магазинной части этого пункта нельзя отмечать полной до проверки с Google Play. Fallback цен — согласованное пользователем исключение; настоящие покупки и восстановление требуют внешней настройки. Настройка описана в README.

## Дополнения в версии 1.1

- Backend опубликован в Cloudflare; телефон использует HTTPS без Mac и общей Wi-Fi сети. Подробности: `cloud.md`.
- Две бесплатные модели в ограниченном fallback OpenRouter; ошибки не скрываются бесконечными ретраями. Пустой результат, терминальная ошибка и отмена возвращают резерв бесплатного сообщения.
- Markdown появляется постепенно, с фиолетовым курсором. Есть переходы между экранами и анимация нажатий. Полученный текст сохраняется независимо от визуальной анимации.
- Проверки Cloudflare: 6/6; локального backend: 8/8. Новые Android-сценарии: автоматический пейвол, удаление, Room, клавиатура. Актуальный протокол — `acceptance.md`.
- Указанные выше LAN APK и ранние записи относятся к предыдущей версии. Актуальный APK использует Cloudflare.
- Без настройки Play Console реальные цены недоступны. ТЗ разрешает мок покупки, но отдельно требует магазинные цены: подстановка цен из макета не закрывает этот пункт. Публичная публикация не обязательна; можно использовать license testers/внутренний тестовый трек.

Последующее согласованное изменение: пользователь разрешил fallback именно для цен. Runtime деморежим AI и фиктивная покупка по-прежнему отсутствуют. Печатание замедлено до одного Unicode-символа за 32 мс без ускорения по размеру очереди; пейвол ждёт окончания визуального вывода.
