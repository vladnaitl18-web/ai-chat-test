# AI Чат — Android test assignment

Kotlin + Jetpack Compose, Coroutines/Flow, Room. Пять состояний из задания: пустой чат, потоковый ответ, ошибка, история и пейвол. В проекте **нет деморежимов, встроенных ответов AI или поддельных покупок**. Без ключа OpenRouter запрос показывает ошибку настройки; бесплатный лимит при этом не расходуется.

## Запуск

Нужны JDK 17 или 21 и Android SDK 36. Android Studio может использовать Embedded JDK. По умолчанию APK обращается к опубликованному HTTPS backend:

`https://ai-chat-android-test.vladius-apps-bd9433.workers.dev/`

Mac, общая Wi-Fi сеть и локальный сервер телефону больше не нужны. Достаточно интернета.

```sh
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Свой облачный backend: [docs/cloud.md](docs/cloud.md). Ключ OpenRouter хранится только в Cloudflare Secret, не в APK/BuildConfig/Git. Основная бесплатная модель — `nvidia/nemotron-3-super-120b-a12b:free`, резервная — `qwen/qwen3.8-27b:free`. В OpenRouter передаётся ограниченный список двух моделей и нулевая максимальная цена. Бесплатные провайдеры могут быть временно недоступны.

Локальный вариант для разработки (Node.js 22+):

```sh
cd server
cp .env.example .env
# Заполнить OPENROUTER_API_KEY. .env исключён из Git.
npm start
```

В другом терминале из корня проекта:

```sh
./gradlew assembleDebug -PapiUrl=http://10.0.2.2:8787/
```

Backend по умолчанию слушает `127.0.0.1:8787`. Для телефона через USB доступны `adb reverse tcp:8787 tcp:8787` и сборка с `-PapiUrl=http://127.0.0.1:8787/`. Cleartext разрешён только в debug; release требует HTTPS и собственного подписания. `local.properties` создаётся Android Studio и исключён из Git.

## Что реализовано

- Первый запуск: случайный UUID установки (`device_id`), получение access/refresh токенов, онбординг. Токены зашифрованы Android Keystore (AES-GCM), резервное копирование отключено.
- Пустое/пробельное сообщение отправить нельзя. Примеры запросов подставляют текст. В пустом чате нет неработающих плюсов; в переписке кнопка лампочки открывает подсказки.
- Серверный лимит: три новых пользовательских запроса на установку. При принятии генерации резервируется одно сообщение. Только успешный непустой ответ расходует его окончательно; ошибка провайдера, пустой результат или отмена возвращают резерв ровно один раз. `request_id` защищает повторную отправку от двойного списания в пределах срока хранения генерации. Отсутствующий API-ключ не расходует лимит.
- Ответ OpenRouter приходит по SSE. Markdown отображается через Markwon (заголовки, списки, выделение, ссылки, блоки кода).
- Каждый фрагмент с его event ID атомарно сохраняется в Room. Повторно доставленные события игнорируются.
- «Стоп» отменяет клиентский HTTP-запрос и отправляет backend отмену генерации. Частичный ответ остаётся в истории. Остановка обработки у конкретного провайдера зависит от поддержки отмены OpenRouter.
- Auth refresh сериализован через Mutex: конкурентные запросы не обновляют токен одновременно. При истечении токена в SSE клиент обновляет авторизацию и подключается к **той же** генерации с сохранённого event ID. Уже полученный текст не теряется и не повторяется.
- При разрыве клиентской сети показывается ошибка и ручной «Повторить». Backend продолжает ограниченную по времени генерацию и хранит события для возобновления. Автоматических сетевых ретраев нет; автоматический refresh ограничен тремя попытками на стрим, обычный HTTP — одним повтором после refresh. Сетевые ошибки не очищают токены.
- При окончательной ошибке самого AI-провайдера прежний частичный ответ остаётся в истории. Ручной повтор создаёт **отдельный ответ на исходный вопрос**, с новым резервированием ранее возвращённого сообщения; максимум три таких повтора. В итоге лимит расходует только успешный ответ. Продолжение исходной генерации у завершившего её провайдера не имитируется.
- Добавлены плавные переходы экранов, отклик кнопок и постепенное появление Markdown с фиолетовым курсором: один Unicode-символ за 32 мс, паузы 65–110 мс на пунктуации, без ускорения для крупных SSE-чанков. Анимация не задерживает сохранение полученного текста в Room.
- При переходах закрываются клавиатура и фокус; ввод и список учитывают IME insets, многострочный ввод ограничен по высоте.
- После последнего успешного бесплатного ответа пейвол открывается автоматически, когда визуальное печатание заканчивается. При отмене или ошибке резерв возвращается, пейвол из-за временного резервирования не открывается.
- Удаление чата с подтверждением удаляет его сообщения через внешний ключ Room.
- История Room переживает перезапуск; незавершённый стрим становится восстанавливаемой ошибкой. Название — первые 55 символов первого сообщения, поиск по названию, группы «Сегодня», «Вчера», «Ранее».
- Google Play Billing: цены из ProductDetails, выбор тарифа, стандартное окно покупки, обработка pending/cancelled, восстановление через queryPurchasesAsync, серверная проверка чека, acknowledge после проверки. При запуске проверяются сохранённый доступ и покупки магазина.
- Настройки: статус подписки, восстановление, управление подпиской в Google Play, Rate App, условия и информация о данных.

## Google Play: обязательная внешняя настройка

По согласованию с пользователем добавлен fallback цен: если магазин не вернул продукты, отображаются 499 ₽/неделя и 1 290 ₽/месяц с явной пометкой «ТЕСТОВЫЕ ЦЕНЫ». Настоящие ProductDetails имеют приоритет. Кнопка покупки для тестовых цен недоступна: успешная покупка и PRO-доступ не подделываются. «Восстановить покупки» обращается к настоящему Google Play. Это согласованное исключение к пункту ТЗ про цены из стора, а не доказательство работающей магазинной оплаты.

1. Создать приложение с application ID `dev.test.aichat` (или изменить ID и `ANDROID_PACKAGE` согласованно).
2. Создать и активировать подписки `chat_weekly` и `chat_monthly`, базовые планы на неделю и месяц, настроить цены и доступные регионы.
3. Загрузить подписанную сборку в internal testing, добавить license testers и установить приложение через тестовый трек.
4. Разрешить сервисному аккаунту Google Play Developer API читать покупки. Для Cloudflare JSON задаётся секретом `GOOGLE_SERVICE_ACCOUNT_JSON`; для локального Node — путём `GOOGLE_SERVICE_ACCOUNT_FILE`. JSON с ключом нельзя помещать в репозиторий.
5. Backend проверяет `purchases.subscriptionsv2.get`: допустимый product ID, состояние и дату окончания. Восстановление на новой установке переносит доступ по проверенному чеку; прежняя установка теряет этот доступ. Сервер повторно проверяет сохранённый чек при запросе аккаунта (кеш до 60 секунд).

Без Play Console и сервисного аккаунта нельзя проверить реальную покупку, восстановление и цены. Интеграция в коде не означает, что товары уже существуют в магазине.

## Проверки

```sh
node --test server/server.test.mjs server/provider.test.mjs
# Cloudflare: команды сборки тестового bundle и Miniflare — docs/cloud.md
./gradlew testDebugUnitTest lintDebug
./gradlew connectedDebugAndroidTest
```

Тестовые сетевые фикстуры существуют только в тестах. Они не доступны как режим приложения или сервера.

Backend-тесты покрывают сохранение лимита, идемпотентность, пейвол, отсутствие ключа без списания, refresh посреди SSE, возобновление после отключения клиента, остановку, повтор после ошибки провайдера и изоляцию устройств. JVM-тесты проверяют SSE framing, конкурентный refresh и ограничение повторов. Android-тест открывает реальную Room базу повторно и проверяет сохранение текста/курсора и защиту от дублей.

Ручной сценарий и запись видео: [docs/acceptance.md](docs/acceptance.md). API: [docs/api.md](docs/api.md).

## Структура

```text
app/src/main/java/dev/test/aichat/
  ui/          Compose и ViewModel
  data/        Room, ChatRepository, состояния сообщений
  network/     OkHttp, SSE parser, Auth, Keystore
  billing/     Google Play Billing
cloud/         Cloudflare Worker + SQLite Durable Objects
server/        Локальный HTTP/SSE backend Node.js; общий prompt для двух реализаций
```

Один app-модуль и явные зависимости без DI-фреймворка: достаточно для небольшого тестового. UI получает состояние через StateFlow; сеть не выполняется в главном потоке. Облачный backend хранит аккаунты, сессии и события в SQLite Durable Objects. Локальный Node хранит аккаунты/сессии в `server/data/state.json`, AI-события — в памяти.

## Границы и то, что нужно перед публикацией

- Реальные ответы OpenRouter проверены с локальным ключом; для другой установки backend нужен собственный ключ. Системная инструкция задаёт русский язык, краткость и запрет выдуманных деталей. Качество AI не гарантируется одним промптом; бесплатный провайдер может временно вернуть перегрузку.
- Облачные события сохраняются до часа, завершённые потоки переживают пересоздание Durable Object. Незавершённая генерация после потери выполняющего её процесса фиксируется как ошибка с возвратом резерва; продолжение вычисления провайдера после такого сбоя не обещается. Ограничены размер запроса, время генерации, параллельность и повторы. Для production нужны мониторинг нагрузки, политика хранения и защита от новых установок. Локальный Node-вариант остаётся однопроцессным с буфером событий в памяти.
- Идентификатор установки без пользовательского аккаунта — компромисс ТЗ. Переустановка создаёт новый device_id и бесплатный лимит; это не полноценная защита от злоупотребления.
- Для production нужны уведомления Google Play RTDN/согласованная актуализация подписок, поддержка возвратов и операционный мониторинг. Сейчас проверка идёт при старте/восстановлении и чтении аккаунта, а не push-уведомлениями.
- Текст пейвола обещает только реализованные функции. Вложения и приоритетная очередь не реализованы и не рекламируются. По последующей просьбе пользователя весь интерфейс переработан: единая светлая тема, карточки, секции настроек, компактный Markdown. Функциональные критерии пяти блоков сохранены в `docs/requirements.md`.
- Информация о конфиденциальности и условиях внутри приложения помечена как описание тестового приложения. До публикации нужны реальные реквизиты владельца, контакты поддержки и окончательные документы. Rate App заработает для опубликованного package ID.
- Приложение не использует рекламу, рекламный ID, камеру, микрофон, геолокацию или чтение файлов. Явно запрашивается только INTERNET; разрешение Billing добавляет SDK. ATT относится к iOS и здесь не применяется.
- Проверка Google Play, заполнение Data safety, release signing и приёмка ПМ не выполнены автоматически и не заявляются как пройденные.

Источники интеграций: [OpenRouter SSE](https://openrouter.ai/docs/api_reference/streaming), [Google Play Billing](https://developer.android.com/google/play/billing/integrate), [Google Play subscriptions API](https://developers.google.com/android-publisher/api-ref/rest/v3/purchases.subscriptionsv2/get).

## Проверенный результат

- Сборка APK 1.1, JVM-тесты и Lint успешны.
- 14 тестов Node backend/резервного ключа, 6 тестов Cloudflare/Miniflare: идемпотентность, возврат лимита, fallback-настройки, SSE resume, refresh, stop, сохранение завершённых потоков после перезапуска.
- Android-прогон облачной версии и клавиатуры: актуальный результат в [docs/acceptance.md](docs/acceptance.md).
- Статус каждого из пяти критериев: [docs/requirements.md](docs/requirements.md).
- Реальные Google Play товары, оплата и восстановление ещё не настроены и не проверены. Fallback из макета явно помечен как тестовый; он не включает фиктивную оплату.

Резервный ключ OpenRouter хранится в `OPENROUTER_API_KEY_BACKUP` на сервере. Максимум одно переключение при 401, 429 или исчерпанном лимите конкретного ключа; общий лимит сервиса может затронуть и резервный аккаунт. Подробности — `docs/cloud.md`.
